Summary at a Glance

Sharflow is an AI Website Watchdog that monitors website performance and search visibility. When you connect Google Search Console, Google Analytics 4, or Bing Webmaster Tools, we access only authorized read-only performance metrics to detect meaningful changes and deliver concise intelligence alerts. We never see, request, or store your passwords. All OAuth refresh tokens are encrypted at rest using AES-256-GCM. We never sell your data, never serve ads, and never use your private data to train generalized AI models.

2. Information We Collect & Stored Data Inventory

We collect only the minimum information required to deliver automated monitoring. Below is an exhaustive inventory of the data categories and MongoDB collections maintained by Sharflow:

A. Account & Profile Data (users collection)

  • Contact details: Display name and email address (used as your unique login identifier, for transactional notifications, and account recovery).
  • Password credentials: Salted and hashed using the industry-standard bcrypt cryptographic algorithm (10 rounds). Plain-text passwords are never recorded or accessible.
  • Website monitoring preferences: Primary website URL, site category, focus goals, tracked keywords, designated high-priority pages, and notification preferences.
  • Monitoring status metadata: Timestamps of the last generated intelligence report and monitoring state.

B. Connected Datasource Credentials (datasources collection)

  • Provider identification: Service name (google_search_console, google_analytics_4, or bing_webmaster), connected property ID and URL.
  • Granted scopes: The explicit list of OAuth scopes authorized during the OAuth consent step.
  • Encrypted OAuth Refresh Tokens: Encrypted at rest using AES-256-GCM authenticated encryption with a unique 12-byte initialization vector (IV) and authentication tag. Plain-text tokens are never stored and never returned to client browsers.
  • Account email & sync timestamps: Associated provider email address and last successful synchronization timestamp.

C. Daily Metric Snapshots (metric_snapshots collection)

  • Aggregated metrics only: Daily aggregate figures for impressions, clicks, click-through rates (CTR), average search positions, sessions, active users, and conversions.
  • Aggregated dimensions: Top search query strings and top landing page paths.
  • No visitor PII: Metric snapshots contain purely aggregated statistics; we never collect individual IP addresses, visitor names, or personal visitor browsing histories from your connected properties.

D. Intelligence Reports (intelligence_reports collection)

  • Historical records of generated watchdog reports, detected anomaly findings, priority-ranked recommendations, and executive summaries.

E. Operational Locks & Delivery Logs (delivery_logs collection)

  • Scheduler execution records and idempotency locks (watchdog_run_<email>_<date>) ensuring daily checks run accurately without duplicate email dispatches.

F. Temporary OAuth State (oauth_pending collection)

  • Cryptographically random CSRF verification tokens generated during active OAuth connection handshakes, automatically purged immediately after the flow completes.

G. Legacy Status Records (digests collection — Read-Only)

  • A historic legacy collection accessed strictly in read-only mode by our status interface to display aggregate delivery statistics. No new user data is written to this collection.

3. Exact OAuth Scopes Requested

Sharflow requests only the minimal read-only scopes necessary to monitor search performance and site visibility. We never request administrative or edit permissions.

Google APIs:

  • https://www.googleapis.com/auth/webmasters.readonly
    Purpose: Read-only access to Google Search Console performance data (clicks, impressions, query rankings, and verified property list) to detect organic traffic drops and momentum shifts.
  • https://www.googleapis.com/auth/analytics.readonly
    Purpose: Read-only access to Google Analytics 4 reporting data (sessions, active users, conversions) to assess site engagement trends.
  • openid, email, profile
    Purpose: Standard Google Identity scopes used strictly to verify your account identity and verify ownership during the OAuth consent handshake.

Bing Webmaster Tools:

  • webmaster.manage
    Purpose: Official Microsoft OAuth scope used in read-only queries to fetch Bing search clicks, impressions, and query performance.

5. How OAuth Tokens Are Protected

We employ strict defense-in-depth measures to secure OAuth credentials:

  • AES-256-GCM Encryption: All OAuth refresh tokens are encrypted at rest using AES-256-GCM. Each token is encrypted using a unique, cryptographically random 12-byte initialization vector (IV) and authenticated with a 16-byte authentication tag (iv:authTag:ciphertext).
  • Memory-Only Decryption: Tokens are decrypted only transiently in memory when our automated scheduler runs to query metrics, and are discarded from memory immediately after the request completes.
  • Zero Client Exposure: OAuth refresh tokens are never included in API responses sent to the browser and are never printed to server logs.
  • Transport Security: All API communication with Google, Microsoft, and database servers occurs exclusively over encrypted TLS 1.3/HTTPS channels.

6. AI Processing of Aggregated Metrics

Sharflow uses artificial intelligence (specifically Google Gemini via the server-side Google GenAI API) to synthesize actionable summaries from your website's performance findings:

  • Aggregated Input Only: The AI model receives only high-level, mathematical findings (e.g., "organic search impressions dropped 34% week-over-week on page /pricing").
  • No Sensitive Data Sent: Passwords, OAuth tokens, personal account credentials, and visitor personal data are never transmitted to the AI model.
  • Conditional Execution: If zero anomalies or significant shifts are detected during a check, the AI call is completely skipped to prevent unnecessary processing.
  • No Public Model Training: Your metric data is processed via commercial API interfaces governed by Google Cloud enterprise terms and is not used to train foundation models.

9. How to Disconnect Datasources & Delete Data

You have full control over your data and connected integrations at all times:

A. Disconnecting in Sharflow

You can disconnect any integration at any time from your Sharflow dashboard settings. When you click disconnect, the associated encrypted refresh token is permanently deleted from our datasources collection immediately.

You can revoke Sharflow's access directly at any time from your provider account:
